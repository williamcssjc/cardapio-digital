# WHITE_LABEL_SYSTEM.md

## Arquitetura de Produto — Parrilla OS

**Versão:** 1.0

**Status:** Documento Fundador

---

# 1. Visão

O Parrilla OS não é um sistema de cardápio digital.

É uma plataforma SaaS para experiências gastronômicas.

O objetivo nunca será apenas receber pedidos.

O objetivo é fazer com que cada restaurante entregue uma experiência digital que pareça ter sido construída exclusivamente para sua marca.

O cliente nunca deve perceber que está usando um software terceirizado.

Ele deve sentir que está utilizando o sistema oficial daquele restaurante.

O Parrilla OS é invisível.

A marca do restaurante sempre aparece em primeiro lugar.

---

# 2. Filosofia

Toda decisão de desenvolvimento deve responder três perguntas.

## Isso melhora a experiência do cliente?

## Isso melhora a operação do restaurante?

## Isso facilita escalar o produto para centenas de restaurantes?

Se qualquer resposta for "não", a implementação deve ser reavaliada.

# 15. UX Philosophy

O cliente nunca deve aprender a usar o sistema.

Ele simplesmente usa.

Toda ação importante deve exigir o menor número possível de toques.

Objetivos.

•

Pedir bebida em menos de 30 segundos.

•

Encontrar um prato em menos de 60 segundos.

•

Pedir conta em menos de dois toques.

•

Chamar o garçom em menos de dois toques.

# 17. Identidade Visual

Durante a construção da V1 utilizaremos o restaurante **+54 Parrilla (São José dos Campos)** como restaurante de referência.

O objetivo não é copiar sua interface.

O objetivo é capturar seu DNA visual.

Serão analisados:

* paleta de cores;
* tipografia;
* estilo fotográfico;
* iluminação;
* composição;
* linguagem;
* identidade da marca;
* materiais gráficos;
* cardápio;
* destaques do Instagram.

A arquitetura deve permitir substituir toda essa identidade por outra configuração sem alterar o código dos componentes.

---

# 18. White Label

O Parrilla OS deverá permitir que um novo restaurante seja configurado alterando apenas dados e ativos visuais.

Nenhum componente deverá precisar ser reescrito para adaptar o produto a uma nova marca.

O objetivo de longo prazo é que a ativação de um novo restaurante seja um processo de configuração, e não de desenvolvimento.

---

# 19. Regra de Ouro

**Toda nova funcionalidade deverá ser implementada perguntando primeiro:**

1. Isso pertence ao Parrilla OS ou ao restaurante?
2. Isso deve ser código ou configuração?
3. Outro restaurante poderia reutilizar essa funcionalidade sem modificações?
4. Essa decisão reduz ou aumenta o custo de manutenção quando houver 100 restaurantes?

Se a resposta aumentar acoplamento, a implementação deve ser revisada antes de seguir.
